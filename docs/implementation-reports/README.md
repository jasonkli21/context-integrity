# Implementation reports

Implementation reports are **delivery evidence**, not requirements.

Create one after substantial phase implementation.

Recommended naming:

```text
phase-0-implementation-report.md
phase-1-implementation-report.md
```

A report should contain:

- commits;
- requirements/acceptance criteria addressed;
- files changed;
- architecture decisions made during implementation;
- tests run and results;
- deviations from the plan;
- known limitations;
- deferred items.

Use explicit labels:

```text
implemented
verified
deferred
```

Do not claim that a planned requirement is delivered merely because it appears in the phase plan.
