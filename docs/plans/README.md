# Implementation plans

Plans are **normative future/current requirements**, not proof of delivered behavior.

Naming:

```text
phase-N-implementation-plan.md
phase-N-M-implementation-plan.md
```

A plan should define:

- objective;
- in/out of scope;
- architecture constraints;
- work breakdown;
- acceptance criteria;
- tests;
- explicit deferrals.

After implementation, do not rewrite the plan to make it match the implementation. Record deviations in the implementation report and resolve durable differences through code, architecture, ADRs, or a new plan.
